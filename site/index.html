01Why not an online unlocker?

The usual answer is to upload the file — and the password — to a website you have never heard of.

Online “unlock PDF” sitesfpr
Where your file goesTheir serverNowhere. It never leaves the disk
Where your password goesTheir serverA wipeable buffer, zeroed on exit
AfterwardsTheir retention policyThere is no “afterwards”
Proof the output is intactNonePage counts and content digests, compared
Works offline / air-gappedNoYes
Strips protection you cannot authenticateUsually yesNo — and that is the point
Most “unlockers” open a PDF with an empty password and re-save it without the permission flags. That is a bypass, not a decryption. This tool refuses unless you supply the owner password — ADR-0008.

02What it will and will not do

Enforced in code, not promised on a page. Every refusal has a test proving it.
✓ WillDecrypt a file when you supply a password its own verifier accepts, and write a new, unencrypted copy
✕ Will notRecover, guess or brute-force a password — no dictionary, no retry loop, no “recovery mode”
✕ Will notStrip permission flags off a document you cannot authenticate against
✕ Will notTouch DRM, Information Rights Management, or certificate-based encryption

iOS / Android

No app, no APK — by design

Decrypting a file means holding the plaintext password and the plaintext file in memory together. That boundary is harder to defend on a general-purpose mobile OS, so no mobile build is shipped rather than shipping one without the same guarantees.

Read why ↗
Verify what you downloaded before you run it: shasum -a 256 -c SHA256SUMS (macOS/Linux) or certutil -hashfile fpr.zip SHA256 (Windows), against the SHA256SUMS on the release page. Standalone bundles are unsigned — Gatekeeper/SmartScreen will say so; that's expected. Not on PyPI yet, so pip install needs the git+ form above.

05How you know it actually worked

A success message is printed only after the written file has been re-read from disk.

1. Capture

Content invariants are taken from the input: page counts, per-page content-stream digests, per-entry SHA-256.

2. Write atomically

Output goes to a 0600 temp file in the destination's own directory, is fsync'd, then renamed into place.

3. Re-open

The file is read back from disk and proved to be unprotected — not assumed from a library call's return value.

4. Compare

The invariants are recomputed and checked against the ones captured from the input.

5. Or fail loudly

Any mismatch scrubs the output and exits 9. A file that cannot be proved good never reaches the name you asked for.

No password on argv

There is no --password VALUE flag. Command lines are readable by every process and land in shell history. Use --password-stdin.

06Built for AI agents too

fpr is a plain CLI with --json output and 13 stable exit codes — any agent with shell access can drive it directly. It never guesses a password; an agent has to be given one explicitly, the same as a human does. 

# machine-readable; the password never touches argv, history, or the environment
$ printf '%s' "$PASSWORD" | fpr --json remove report.pdf --password-stdin
{"ok": true, "output": "report-unprotected.pdf",
 "verification": {"encrypted": "false", "pages": "3", ...}}
